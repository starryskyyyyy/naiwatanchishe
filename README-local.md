# 贪吃蛇个人网站

目前交付游戏主体：居中棋盘、计分、昵称提交和前20名排行榜。蛇头使用参考角色的黄色大眼睛头部，蛇身为黄色，尾巴从黄色渐变到黑色；苹果、梨和桃子均为参考圆润小脸角色生成的透明贴图。

## 运行

需要 Node.js 24 或更新版本，无额外npm依赖。

```powershell
cd D:\myweb
npm start
```

打开 [http://localhost:3000](http://localhost:3000)，停止服务按Ctrl+C。双击index.html也可离线玩游戏，但排行榜必须通过服务器网址使用。页面不依赖在线字体或其他外部资源。

## 玩法

- 20×20方格，蛇初始长度3，140毫秒移动一格。
- 每吃一个水果得1分，身体增长一节，水果只生成在空格。
- 首次开始、重开和每次吃完水果，都会在苹果、梨、桃子中等概率抽取一种，允许连续出现同一种；场上始终只有一个水果。
- 撞墙或撞身体结束，不允许直接反向。
- 填满棋盘通关，理论最高分为400减3，即397分。
- 方向键或WASD移动；空格或P开始/暂停/继续；R重开。
- 手机上可以点方向按钮或在棋盘滑动。
- 切换到后台自动暂停；打开排行榜也暂停，关闭后恢复之前正在进行的游戏。
- 重开后回到准备界面，点击开始或方向键开始新一局。

## 排行榜

游戏结束后输入1～20字符昵称，每局独立记录，同昵称可占多个名次。分数为0～397的整数。按分数降序排列，同分先提交者优先。

仅保存前20名：已有20条且分数不高于第20名时，不执行插入；新分数入榜则在同一数据库事务中删除被挤出的旧记录。没有完整成绩历史。网络失败重试同一局不会重复保存；重试时昵称锁定以保持同一局内容一致。

数据库是 `data/snake.sqlite`，首次启动自动创建，服务重启后保留。备份时先停止服务，再复制数据库文件。

默认每个连接IP每分钟最多提交30次。分数仍由客户端上报，格式校验和去重不等于完整防作弊。

## 代码怎么读

| 文件 | 职责 |
| --- | --- |
| index.html | 中央游戏区、结算表单、排行榜弹窗 |
| styles.css | 页面与手机布局 |
| game-rules.js | 移动、转向、随机水果、碰撞、通关，和画布无关 |
| game.js | 键盘/触摸输入、开始暂停、固定时间步、弹窗 |
| snake-renderer.js | 根据当前状态绘制蛇和对应种类的水果，不修改规则 |
| skin.js | 蛇和三种水果的贴图路径，以及蛇的连接口位置 |
| leaderboard.js | 浏览器HTTP请求、榜单渲染和重试 |
| server.js | 静态文件与排行榜接口 |
| backend/leaderboard.cjs | 输入检查和SQLite前20名事务 |

后端学习说明见 [docs/backend-learning.md](docs/backend-learning.md)。规则层与绘制层分离：`fruit`保存水果的位置和`type`种类，生成时分别抽取空格与种类；渲染器根据`type`选择图片。吃水果改变`score`和`snake`数组，三种水果的得分相同。

## 以后怎么换贴图

先把图片放入assets目录，再修改skin.js的对应路径。具体文件名和朝向见 [assets/README.md](assets/README.md)。设置null可以使用几何占位；图片加载失败也会回退，不影响游玩。

## 接口与部署

GitHub Pages 网页上传步骤见 [docs/github-pages-upload.md](docs/github-pages-upload.md)。上传包只包含前端；全站排行榜仍需要单独部署后端。

- `GET /api/leaderboard` 返回 `{entries,limit:20}`。
- `POST /api/scores` 接收 `{submissionId,nickname,score}`，返回 `{qualified,rank,duplicate,entries}`。
- 可配置环境变量PORT（默认3000）、HOST（默认127.0.0.1）、DATA_DIR（默认项目data目录）。
- 目前本地运行。部署需要Node.js服务和持久磁盘，仅上传到GitHub Pages无法运行后端。
- 默认不信任代理IP头；以后部署反向代理时需要配置，否则玩家可能共用限流额度。
